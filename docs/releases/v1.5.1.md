# secure-vps v1.5.1

Corrige el cierre de SSH cuando una configuración anterior del proveedor mantiene `PasswordAuthentication yes`. Kenroka incluye sus políticas globales al principio de `sshd_config`, verifica el acceso efectivo del administrador y de root, y restaura los cambios si un bloque Match contradice la política.

- Migra `99-hardening.conf` a `/etc/ssh/secure-vps.conf`, conservando puertos y restricciones previas.
- Los snapshots conservan el archivo principal y ambas rutas para restaurar exactamente el estado anterior.
- Conserva las pruebas externas de clave y sudo, la protección temporizada, UFW y Fail2ban.
- Incluye los cambios de interfaz y verificación presentes en main desde la release estable anterior.

Esta es una release estable y pasa a ser la versión predeterminada del instalador:

```bash
curl -fsSL https://raw.githubusercontent.com/all-lopezg/kenroka/main/install.sh | bash
```

El instalador verifica la firma y el checksum antes de ejecutar el asistente. Assets: `secure-vps.sh`, `SHA256SUMS.txt` y `SHA256SUMS.txt.sig`.

Validación de la corrección: 601 comprobaciones unitarias, 30 del instalador, 23/23 escenarios de integración en Ubuntu 26.04.1 arm64 (377 comprobaciones externas y 34 internas), tras adaptar y repetir dos pruebas obsoletas. Incluye SSH real y sudo en los tres checkpoints, conflicto de precedencia del proveedor, UFW, Fail2ban, cambio de puerto, restauración automática, migración y bloques Match incompatibles. La preparación de esta release cambia únicamente la versión declarada del script.

Ubuntu 26.04 conserva el alcance experimental explícito: amd64, reinicio real de VM/VPS y migración de sistema operativo desde 24.04 siguen pendientes. La publicación estable del instalador no amplía esos resultados. Ubuntu 22.04 y 24.04 conservan sus rutas de soporte.

Informe: https://github.com/all-lopezg/kenroka/blob/main/docs/validacion-ubuntu-26.04-ssh.md
