# secure-vps v1.5.2

Corrige el fallo de la fase 3 `gawk: fatal: cannot use gawk builtin include as variable name`. La instalación del Include SSH empleaba `include` como variable awk: GNU awk 5.3.2 lo reserva, aunque mawk aceptaba la expresión.

El helper usa ahora `managed_line` y conserva el orden de lectura de las políticas SSH, la idempotencia y la restauración segura. Las pruebas Docker instalan GNU awk para reproducir la configuración del VPS afectado; una regresión ejecuta el helper tanto con GNU awk como con mawk y reproduce primero el error anterior.

Validación previa a la publicación en Ubuntu 26.04.1 arm64, GNU awk 5.3.2:

- 601 comprobaciones unitarias aprobadas.
- Escenario 25: ambas implementaciones awk, 4 comprobaciones externas y 15 internas aprobadas.
- Escenario 23: migración, bloques Match y restauración exacta, 8 externas y 15 internas aprobadas.
- Escenario 05: hardening completo con conflicto de proveedor, acceso SSH real, UFW y Fail2ban, 19 comprobaciones aprobadas.
- Instalador local: 30 comprobaciones aprobadas.

Release estable firmada: el comando habitual descarga esta corrección sin cambiar la URL:

```bash
curl -fsSL https://raw.githubusercontent.com/all-lopezg/kenroka/main/install.sh | bash
```

Ubuntu 26.04 mantiene el alcance experimental documentado: esta validación es Docker arm64; amd64, reinicio real de VM/VPS y migración de sistema operativo siguen pendientes.

Validación posterior a la publicación: escenario 24 aprobado con 14 comprobaciones, 0 fallos, sobre Ubuntu 26.04.1 arm64 con GNU awk por defecto. El comando público exacto descarga y verifica v1.5.2 y abre el menú. La guía desde la misma release pública supera tres conexiones SSH/sudo reales, termina el hardening y conserva el acceso del administrador con UFW y Fail2ban activos.
